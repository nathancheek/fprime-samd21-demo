## Building and Running the SAMD21DemoDeployment Application

In order to build the SAMD21DemoDeployment application, or any other F´ application, we first need to generate a build directory. This can be done with the following commands:

```sh
cd SAMD21Demo/SAMD21DemoDeployment
fprime-util generate
```

The next step is to build the SAMD21DemoDeployment application's code. Build from the deployment's folder: building from the project root also builds every F´ framework module, and some of them don't build for Arduino boards.
```sh
fprime-util build
```

## Flashing the ATSAMD21J17D

The deployment has no bootloader: it starts at address 0 and is flashed over SWD with a debug probe (CMSIS-DAP, J-Link, Atmel-ICE). It assumes the Arduino Zero's 32.768 kHz crystal on PA00/PA01 (see `lib/fprime-arduino/cmake/toolchain/ATSAMD21J17D.cmake`). With OpenOCD and a CMSIS-DAP probe, from the project root:

```sh
openocd -f interface/cmsis-dap.cfg -c "set CHIPNAME at91samd21j17" -f target/at91samdXX.cfg -c "program ./build-artifacts/ATSAMD21J17D/SAMD21Demo_SAMD21DemoDeployment/bin/SAMD21Demo_SAMD21DemoDeployment.elf verify reset exit"
```

This hasn't been tried on hardware. OpenOCD identifies the chip by its device ID, so an older OpenOCD may not recognize the J17D.

Pins follow the Arduino Zero: the LED is on PA17, console output (`Fw::Logger`) is on Serial (SERCOM5, TX on PB22, RX on PB23), and the Space Packet link is on Serial1 (SERCOM0, TX on PA10, RX on PA11).

## Running the application and F' GDS

The Space Packet link on Serial1 (F' GDS on the bench, another subsystem in flight) carries CCSDS Space Packets, each starting with a 2-byte sync word (0xC1F5) and ending in a 2-byte CRC (see `SAMD21Demo/Components/ComSpacePacket`), with no TC/TM transfer frames. The sync word (`ComCfg.SpacePacketSyncWord`, 0 for none), the CRC (`ComCfg.SpacePacketCrc`) and the APIDs (`ComCfg.Apid`) are set in `config/ComCfg.fpp`. F' GDS reads this format through the framing plugin in `gds/space_packet_crc.py`, which takes all three from the dictionary. From the project root:

```sh
export PYTHONPATH="$PWD/gds"
export FPRIME_GDS_EXTRA_PLUGINS="space_packet_crc:SpacePacketCrcFramerDeframer"
fprime-gds -n --dictionary ./build-artifacts/ATSAMD21J17D/SAMD21Demo_SAMD21DemoDeployment/dict/SAMD21DemoDeploymentTopologyDictionary.json --framing-selection space-packet-crc --communication-selection uart --uart-device /dev/ttyACM0 --uart-baud 115200
```

> [!NOTE]
> `/dev/ttyACM0` should be the serial adapter on Serial1. It may vary for your system/device. It may also be `/dev/ttyUSB0`. For MacOS, it will be along the lines of `/dev/tty.usbmodem12345`. Change accordingly.
>
> To view the list of your connected devices, run: `ls /dev/tty*`.

All telemetry is sent once per second via packetized telemetry packets, defined in `Top/SAMD21DemoPackets.fppi`. There are no events: command results show up in the `cmdDisp.CommandsDispatched` and `cmdDisp.CommandErrors` channels.

The LED blinks once a second. `lifeLed.LED_PERIOD_PRM_SET` changes its period (in 10 Hz ticks, at least 1) until the next reset. Parameters have no storage yet, so `lifeLed.LED_PERIOD_PRM_SAVE` fails.
